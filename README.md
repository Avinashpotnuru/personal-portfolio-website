## Rendering Architecture

This project follows Next.js App Router best practices with a clear separation of Server and Client Components.

| Route | Strategy | Details |
| --- | --- | --- |
| `/` | **Static (○)** | Server Component page composing static `About` and `MyProjects` components. |
| `/about` | **Static (○)** | Server Component page. Interactive tabs handled by client-side `FullDeatils`. |
| `/blog` | **Static (○)** | Lists blog posts from static data. |
| `/blog/[slug]` | **SSG (●)** | Pre-rendered at build time via `generateStaticParams()`. `dynamicParams = false` ensures unknown slugs return 404. |
| `/projects` | **Static (○)** | Server Component page. Project filtering handled by client-side `ProjectsFilter`. |
| `/projects/[id]` | **SSG (●)** | Pre-rendered at build time via `generateStaticParams()` for all project slugs. `dynamicParams = false`. |
| `/contact-us` | **Static (○)** | Server Component page. Form modal interaction handled by client components. |
| `/course-certificates` | **Static (○)** | Statically rendered page. |
| `/api/add-client-details` | **Server Route (λ)** | POST handler for saving contact details to MongoDB. Marked `force-dynamic`. |
| `/api/client-details` | **Server Route (λ)** | GET handler for fetching client details. Marked `force-dynamic`. |

**Key Principles:**
- **Server Components by default** - Most components are server-rendered for optimal performance.
- **Minimal client boundaries** - `"use client"` is only used where necessary (state, effects, event handlers, browser APIs).
- **Static-first approach** - Content-heavy pages are statically generated. Only routes requiring runtime data use server execution.
- **Server-only protection** - Database modules use `server-only` to prevent accidental client bundling.

## Getting Started

### Prerequisites

- [Node.js](https://nodejs.org/) 18.x or later
- [pnpm](https://pnpm.io/) (this project uses `pnpm@11.13.1`)

### Installation

```bash
# Clone the repository
git clone https://github.com/Avinashpotnuru/personal-portfolio-website.git

# Navigate to the project directory
cd personal-portfolio-website

# Install dependencies
pnpm install

# Start the development server
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser to view the site.

## Environment Variables

Create a `.env.local` file in the root directory with the following variables:

```env
# Base URL for sitemap and SEO
NEXT_PUBLIC_SITE_URL=https://yourdomain.com

# MongoDB connection string (for API routes)
MONGODB_URI=your_mongodb_atlas_connection_string

# EmailJS credentials (for contact form)
NEXT_PUBLIC_EMAILJS_SERVICE_ID=your_service_id
NEXT_PUBLIC_EMAILJS_TEMPLATE_ID=your_template_id
NEXT_PUBLIC_EMAILJS_PUBLIC_KEY=your_public_key
```

> **Note:** The contact form uses EmailJS directly from the client. The MongoDB API routes are available for alternative implementations.

## SEO & Metadata

- **Global Metadata** - Configured in `app/layout.js` with title template, description, keywords, OpenGraph, and Twitter cards.
- **Per-page Metadata** - Each page defines its own title and description.
- **JSON-LD** - Person schema added to root layout for rich search results.
- **Sitemap** - Auto-generated at `/sitemap.xml` via `app/sitemap.js` covering all static routes, blog posts, and project pages.
- **Robots** - Configured at `/robots.txt` via `app/robots.js`.
- **Canonical URLs** - Handled via `metadataBase` in root layout.

## Contact Form Flow

1. User clicks "Contact Us" on the Contact page → Opens `ContactPopup` (Client Component)
2. Form validation handled by React Hook Form
3. On submit, form data is passed to `DetailsPopup` via Redux
4. User confirms details → `DetailsPopup` sends email via EmailJS using public credentials
5. Success/failure feedback shown via React Toastify
